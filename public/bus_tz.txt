ТЗ: АВТОМАТИЧЕСКАЯ СИСТЕМА ОБЩЕСТВЕННОГО ТРАНСПОРТА (2D GAME)

ВЕРСИЯ: 1.0

---

### 1. ОБЩИЕ СВЕДЕНИЯ И АРХИТЕКТУРНЫЙ ПРИНЦИП

Цель: Реализовать серверную (авторитетную) систему общественного транспорта для 2D-игры. Автобусы движутся по заданным круговым маршрутам строго по расписанию, независимо от онлайна игроков или водителей. Клиентская часть только отображает состояние, получаемое от сервера.

Ключевой принцип: **Клиент не принимает решений. Клиент лишь визуализирует данные сервера.**

Сервер хранит не координаты, а "временные точки" (таймстемпы прибытия/отправления). Клиент вычисляет текущую позицию автобуса путем интерполяции между остановками на основе синхронизированного серверного времени.

---

### 2. ОСНОВНЫЕ СУЩНОСТИ (БАЗА ДАННЫХ / СТРУКТУРЫ)

#### 2.1. Маршрут (Route)
*   `id`: UUID/Int (Уникальный идентификатор маршрута)
*   `name`: String (Номер/название, например, "№12")
*   `stops`: List<StopID> (Упорядоченный список ID остановок по ходу движения)
*   `travel_times`: Map<StopIndex, Seconds> (Время в пути от текущей остановки до следующей)
*   `stop_duration`: Seconds (Время стоянки на каждой остановке)
*   `fare`: Int (Стоимость проезда)
*   `currency_id`: UUID (Тип валюты)

#### 2.2. Остановка (Stop)
*   `id`: UUID/Int
*   `name`: String
*   `location`: Vector2 (Координаты X, Y для 2D мира)
*   `served_routes`: List<RouteID> (Список маршрутов, проходящих через эту остановку)

#### 2.3. Автобус (Bus) - Экземпляр на линии
*   `id`: UUID (Уникальный ID конкретного автобуса, например, "№12-03")
*   `route_id`: UUID
*   `capacity`: Int (Вместимость пассажиров)
*   `current_stop_index`: Int (Индекс в списке `route.stops`)
*   `state`: Enum (MOVING, STOPPED, FINISHED)
*   `departure_time_utc`: Timestamp (Время отправления с `current_stop_index`)
*   `arrival_time_utc`: Timestamp (Время прибытия на `next_stop_index`)
*   `driver_id`: UUID (Nullable, кто управляет сейчас)

#### 2.4. Активная поездка водителя (DriverSession)
*   `id`: UUID
*   `driver_id`: UUID
*   `bus_id`: UUID
*   `route_id`: UUID
*   `start_time_utc`: Timestamp
*   `end_time_utc`: Timestamp (Nullable)
*   `total_earned`: Int
*   `passengers_count`: Int (Всего перевезено за смену)

#### 2.5. Поездка пассажира (PassengerTrip)
*   `id`: UUID
*   `player_id`: UUID
*   `bus_id`: UUID
*   `route_id`: UUID
*   `boarding_stop_index`: Int
*   `exit_stop_index`: Int
*   `start_time_utc`: Timestamp
*   `status`: Enum (ACTIVE, COMPLETED, LEFT_EARLY)
*   `paid_fare`: Int

### 3. ЛОГИКА РАБОТЫ СИСТЕМЫ

#### 3.1. Движение и Расписание (Server-Side)
Маршруты являются круговыми. Обратный маршрут заводится как отдельная сущность.

Сервер оперирует дискретными временными точками для каждого автобуса.
Пример цикла:
1. Автобус на "Автовокзал" (индекс 0).
2. Время отправления (`departure_time_utc`) = 18:00:00.
3. Время в пути до "Центр" (индекс 1) = 40 сек.
4. Время стоянки = 10 сек.
5. Сервер рассчитывает:
    - Прибытие в "Центр": 18:00:40 (состояние меняется на `STOPPED`).
    - Отправление из "Центр": 18:00:50 (состояние меняется на `MOVING`, `current_stop_index` = 1).
    - Прибытие в "Больница": 18:01:25... и т.д.

**Важно:** Если автобус достиг последней остановки маршрута, он переходит в статус `FINISHED`. После этого он либо удаляется, либо (по усмотрению геймдизайна) начинает новый рейс с `current_stop_index = 0` и новым расписанием.

#### 3.2. Клиентская интерполяция (Client-Side)
Клиент получает от сервера `Bus` объект с `departure_time_utc`, `arrival_time_utc`, `current_stop_index`, `next_stop_index`.

Используя синхронизированное серверное время (`now_utc`):
1. Если `now_utc` >= `arrival_time_utc`, автобус находится на остановке `next_stop_index`.
2. Если `now_utc` между `departure_time_utc` и `arrival_time_utc`, клиент вычисляет процент пути (`p`) и интерполирует позицию между координатами `current_stop` и `next_stop`.

#### 3.3. Пассажир (Passenger Flow)
1. **Запрос расписания:** Игрок на остановке делает GET запрос (см. API). Сервер фильтрует автобусы по `served_routes` и вычисляет ETA для каждого.
2. **Посадка:** Игрок вызывает POST `/board`.
    - Валидация сервера: игрок рядом с остановкой, автобус *реально* на этой остановке (по таймингам), есть свободные места, у игрока есть деньги.
    - Списывается `route.fare`.
    - Игрок добавляется в список пассажиров автобуса в БД.
3. **Выбор/Смена остановки:** Игрок может изменить `exit_stop_index` (POST `/change-destination`) на любую остановку, следующую *после* текущей по ходу движения.
4. **Высадка:**
    - Автобус прибывает на остановку (наступает `arrival_time_utc`).
    - Сервер проверяет список пассажиров автобуса.
    - Все, у кого `exit_stop_index` совпадает с текущим, автоматически высаживаются (телепортируются на координаты остановки).
    - **Кейс "Уснул в автобусе":** Если автобус доехал до конечной остановки круга, все оставшиеся пассажиры принудительно высаживаются.

#### 3.4. Водитель (Driver Flow)
1. Игрок выбирает роль, вызывает POST `/driver/start`.
2. Сервер назначает игрока на свободный автобус (или создает новый экземпляр) и возвращает данные рейса.
3. Водитель получает только READ-ONLY информацию (экран из ТЗ). Он не управляет автобусом.
4. Время смены идет непрерывно на сервере. Если водитель отключается, автобус едет по расписанию.
5. При завершении маршрута (последняя остановка) происходит расчет зарплаты и закрытие смены.

### 4. API (REST / WebSocket)

Все запросы, требующие авторизации, должны содержать `Player-Token`.

#### Пассажир (Passenger)
*   `GET /transport/stops/{stop_id}`
    *   Ответ: Список ближайших автобусов с ETA, отсортированных по направлению.
*   `POST /transport/passenger/board`
    *   Body: `{"player_id": UUID, "bus_id": UUID, "exit_stop_index": Int}`
*   `POST /transport/passenger/change-destination`
    *   Body: `{"player_id": UUID, "new_exit_stop_index": Int}`
*   `POST /transport/passenger/exit`
    *   Body: `{"player_id": UUID}` (Опционально, т.к. высадка автоматическая).

#### Водитель (Driver)
*   `POST /transport/driver/start`
    *   Body: `{"player_id": UUID, "route_id": UUID}` (Если маршрут не выбран, назначается любой свободный).
*   `GET /transport/driver/current-session`
    *   Ответ: Текущее состояние автобуса, таймеры, количество пассажиров.
*   `GET /transport/driver/current-session/log`
    *   Ответ: Последние 10 событий посадки/высадки.
*   `POST /transport/driver/finish`
    *   Body: `{"session_id": UUID}`

#### Общее
*   `GET /transport/buses/{bus_id}`
    *   Получить актуальные данные автобуса для точной интерполяции на клиенте.

### 5. ОБЯЗАТЕЛЬНЫЕ ТРЕБОВАНИЯ И КРАЕВЫЕ УСЛОВИЯ

Реализация должна корректно обрабатывать следующие ситуации:

1.  **Автономность:** Автобусы не останавливаются при выключении сервера или отключении всех игроков. Расписание рассчитывается математически от `Unix Time` старта.
2.  **Перезапуск клиента:** При повторном входе в игру пассажир должен оказаться в том же автобусе, на той же позиции (рассчитанной клиентом по времени), с тем же пунктом назначения.
3.  **Вместимость:** Реализовать лимит мест в автобусе (например, 30 человек). Если автобус полный, POST `/board` возвращает ошибку.
4.  **Синхронизация времени:** Клиент должен использовать время сервера для расчета ETA и позиции. Критична защита от ускорения времени на клиенте.
5.  **Конкурентность:** Обработка одновременной посадки 5-ти игроков на одной остановке.
6.  **Деньги:** Проверка баланса игрока перед списанием стоимости проезда.
7.  **Валидация высадки:** Игрок не может выйти из автобуса "в поле", только на остановке (текущей или будущей по маршруту).
8.  **Администрирование:** Возможность администратором игры удалить маршрут или автобус "на лету". Пассажиры такого автобуса должны быть автоматически телепортированы на ближайшую остановку.
